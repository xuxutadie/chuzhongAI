# AI初中学习教练系统_Agent智能体开发指令_V1.0

## 一、开发目标

当前阶段开发 AI 初中学习教练系统的 Agent 智能体基础框架。

目标：

建立一个可扩展的 AI 教育智能体系统。

本阶段重点验证：

学生数据 → AI分析 → 学习计划 → 学习反馈 → 教练调整

完整闭环。

------------------------------------------------------------------------

# 二、当前开发范围

本阶段开发以下5个Agent：

## 1. 学生诊断 Agent

职责：

分析学生当前学习状态。

输入：

-   年级
-   学校
-   当前成绩
-   学习目标
-   学习习惯
-   学科情况

输出：

《学生学习诊断报告》

示例：

``` json
{
  "student":"张同学",
  "grade":"初一",
  "analysis":{
    "数学":"基础较好，需要加强计算准确率",
    "英语":"词汇积累不足",
    "语文":"阅读理解能力需要提升"
  },
  "recommendation":[
    "每日英语词汇20分钟",
    "数学计算专项训练"
  ]
}
```

------------------------------------------------------------------------

## 2. 学习规划 Agent

职责：

根据学生画像生成学习计划。

输入：

-   学习诊断结果
-   可用时间
-   学习目标

输出：

每日学习计划。

要求：

计划必须考虑：

-   学生能力
-   时间限制
-   目标方向

------------------------------------------------------------------------

## 3. 学科辅导 Agent

第一阶段支持：

-   数学
-   英语
-   语文

功能：

学生输入问题后：

1.  判断知识点
2.  分析错误原因
3.  引导学生思考
4.  提供练习建议

禁止：

直接输出答案。

教学模式：

模拟优秀教师教学。

------------------------------------------------------------------------

## 4. 学习评价 Agent

职责：

分析学生学习过程。

输入：

-   任务完成情况
-   测试成绩
-   错题记录

输出：

周学习成长报告。

内容包括：

-   当前进步
-   优势能力
-   薄弱方向
-   下一阶段建议

------------------------------------------------------------------------

## 5. 教练辅助 Agent

面向教师/导师。

功能：

帮助教练管理学生。

输出：

风险提醒。

例如：

学生连续多天未完成任务时：

提醒教练进行沟通或调整计划。

------------------------------------------------------------------------

# 三、Agent系统架构

建立目录：

    agents/

    ├── diagnosis_agent/

    ├── planner_agent/

    ├── tutor_agent/

    ├── evaluation_agent/

    └── coach_agent/

每个Agent包含：

    agent_name/

    ├── README.md

    ├── prompt.md

    ├── service.py

    └── test.py

------------------------------------------------------------------------

# 四、大模型接口设计

不要绑定单一模型。

建立统一接口：

    LLMGateway

支持未来接入：

-   DeepSeek
-   Qwen
-   GPT
-   豆包

调用结构：

    Agent

    ↓

    LLM Gateway

    ↓

    大模型API

------------------------------------------------------------------------

# 五、数据库关联

Agent需要读取：

-   student_profile
-   learning_task
-   exam_record
-   wrong_question
-   study_report

要求：

Agent禁止直接修改数据库。

流程：

Agent输出结果

↓

业务层审核

↓

数据库保存

# 七、开发要求

Codex执行原则：

1.  不一次生成全部业务代码。
2.  每完成一个Agent必须测试。
3.  保持模块独立。
4.  支持未来RAG知识库接入。
5.  不提前开发收费、商城等无关功能。
