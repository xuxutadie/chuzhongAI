# 教师知识库：题库、教材与 AI 变式出题

日期：2026-09-28

状态：用户于 2026-09-28 回复“开始吧”，确认本书面方案，进入实施计划阶段。本文不是功能已上线的说明，尚未实施数据库迁移。

## 1. 目标与已有基础

教师端新增统一“知识库”入口，内部区分“题库”和“教材”。教材限定知识范围，题库提供题型和解法参考，AI 根据审核后的资源生成变式题，供测试与练习使用。仍只开放数学。

当前已存在教师身份、师生关联、学情查看、静态教材目录和本地文档解析代码；不把这些基础等同于已完成知识库或教师发卷。主要复用点：

- `backend/app/api/routes/teacher.py`：教师会话与角色检查。
- `backend/app/teacher_assessment/extractors.py`：受限 PDF、DOCX 和图片解析。
- `frontend/app/teacher/`：教师页面、接口封装和视觉基础。
- `frontend/app/materials/textbook_catalog.js`：现有教材目录；它不是完整的章节知识范围数据库。
- `docs/superpowers/specs/2026-09-26-teacher-question-bank-exams-design.md`：既有测试发布、作答、评分、错题收集的设计依据，不视为已实现。

本方案更新原设计的“我的题库”入口为“知识库 → 题库”，增加教材管理和资源引用规则；不撤销原设计的权限、教师审核和发布快照要求。

## 2. 方案选择与范围

采用统一入口、分开管理、关联引用的方案：两类资源共用私有文件与处理任务能力，但教材章节和题目独立保存。相比仅增加两个静态入口，这样能真正保存、核对和使用内容；相比一次性加入向量数据库、全校共享和自动发卷，首版依赖更少、权限更清晰。

分两个可独立验收的交付阶段，最终目标不缩减：

1. 本轮知识库子模块：题库与教材的上传、解析、人工核对、入库、筛选、预览、归档；基于资源生成可审核的变式草稿和题组，保存原题与教材引用。
2. 后续测试与练习接入子模块：将已审核题组接入教师发布、学生作答、判分、结果与错题收集。沿用原测试方案并另行细化实施计划。不以第一阶段完成宣称第二阶段可用。

不自动替换现有入学测评题库，不改变每日五步路线的完成判定。基础版不增加跨教师共享、公开题库市场或未经审核的自动推题。

## 3. 页面与交互

建议路由为 `/teacher/knowledge`，默认进入题库，页内两个显眼标签“题库”“教材”。保持多巴胺蓝图风格，蓝色主操作、薄荷绿教材、橙色待审核，状态同时有文字，不能仅用颜色区分。

题库页面：

- 首屏主操作“上传题目”“手动录题”，次要操作“生成变式”。空库时引导上传或在已审核教材范围内生成候选题。
- 按年级、教材、章节、知识点、题型、常规／进阶／挑战、审核状态筛选，支持关键词搜索和分页。
- 题目详情包括题干、公式、配图、选项、答案、解析、解题所需知识、来源位置和审核记录。
- 上传后的核对页对照原文与结构化内容，允许修正、拆题、合题、补图。缺答案或范围不明的题只能保存为草稿。

教材页面：

- “上传教材”，填写名称、学科、年级、版本、上下册；按章节组织资料，可对页码或段落范围进行校正。
- 查看原文件、已提取内容、章节目录、关联知识点、配套题和可供 AI 引用的审核状态。
- 自动提取的目录只是候选，教师确认后才成为出题范围。上传文件本身不等于全部内容已识别或审核。
- 原有系统教材只读展示并标注来源，与“我的教材”区分；不自动复制为教师私有文件，也不自动认可为完整课程范围。

桌面核对采用原文和编辑区并排，手机可切换；上传进度、失败原因、重试与保存状态清楚可见。搜索无结果、空库与读取失败使用不同提示。

## 4. 导入与文件边界

流程：上传校验 → 私有保存 → 本地提取 → 必要时请求 OCR／模型整理 → 待核对 → 教师确认入库。

支持 PDF、DOCX、JPEG、PNG、WebP；旧 DOC 提示转存，不声称支持。复用当前已声明的 pypdf、python-docx、Pillow、pypdfium2，不新增依赖，不修改 `.env`。

首版沿用解析器限制：文档单文件 20 MB、图片 5 MB、PDF 最多 50 页。整册教材超限时明确要求按章节拆分上传，同一本教材可以关联多个章节文件；不得悄悄提高限制或截断内容。单次最多 10 个文件、200 道候选题，超限给出分批指引。

校验文件签名、格式、页数、解码像素、解压体积、解析时间；不执行文档脚本、宏或外部链接。图片重编码，文档内容作为资料而非指令。服务端生成文件标识，不使用上传文件名构造存储路径。

PDF 和图片记录页码及区域，DOCX 记录段落位置和图片引用，不伪造 Word 页码。扫描件或不清晰公式明确标为待识别／待核对；没有视觉服务时允许本地解析和手动整理，不能伪报识别完成。

同一教师重复上传相同文件提示复用；相似题只提示，不自动删除。资料默认归档，可恢复；已被审核题组或后续发布记录引用的版本不物理删除。

## 5. 教材决定范围，题库提供参考

生成前确定年级、教材版本、学期、已学章节、知识点和前置要求，形成有版本的范围快照。首批可用范围以项目已审核课程内容为准；未形成审核目录的教材可以保存和预览，但不能直接开放自动出题。

参考题必须属于当前教师或明确可用的系统资源，且已审核、未归档、范围相符。首版采用年级／教材／章节／知识点过滤与关键词检索，不引入向量数据库，不将整个私有资料库一并发送给模型。

教师选择生成方式：

- 原题组卷：引用审核后的题目版本，不改题。
- 变式出题：根据参考题改变数据、情境、提问方式或已学知识组合，生成新的题目版本。
- 混合：教师明确设置原题与变式数量，不暗中替换来源。

常规、进阶、挑战均服从相同知识范围，不能通过引入高一年级内容增加难度。模型自报“符合七年级”不视为证明，需服务端检查知识点标识，并由教师核对实际解法和前置概念。

题库不足时列出缺少的题量、题型或知识点。教师可减少数量、补充资源，或选择按已审核教材范围 AI 补题。空题库生成须标记“依据教材生成，无参考原题”；没有可靠教材范围则阻止生成并说明需补充的资料。

## 6. 变式生成、审核和引用

生成请求携带教师所选范围、难度、题型、题量、有限参考题和教材片段，不发送学生姓名、学校、账号、认领码或其他教师资料。教师服务配置和费用边界沿用原测试设计，无配置时明确提示，不借用学生 API。

变式必须同步生成题干、答案、解析及需要的图形数据；只更改数字而沿用旧答案或旧尺寸图不合格。复杂图形无法可靠生成时保留待补图状态，不以文字描述冒充图形。

每道候选题保存：参考题版本、教材章节版本与页码／段落位置、变式类型、模型与生成时间、检查结果、教师修订和审核记录。引用标识由服务端验证，不能接受模型编造来源。

检查至少覆盖：结构与必填字段、题型和答案格式、选择项一致性、知识范围、必要配图、可确定性验证的计算。无法自动核验的推理标明需要教师审核，不宣称模型绝不会出错。不执行模型返回的任意 HTML、脚本或不受限 SVG。

题目流程：草稿 → 待审核 → 已审核；归档后不能用于新生成或组卷。修改内容、答案、范围或配图产生新草稿版本并使新版本审核失效，不改写旧版本。题组中任何题版本变化都要求重新核对该题组。

教师逐题确认后形成已审核题组，记录用途为测试或练习；本阶段只保存和预览。后续接入时，只有经审核且授权有效的题组可发布，学生作答前不接收答案、解析或原卷文件。课堂练习也不绕过审核；如果没有可用审核内容，应提示等待或明确使用现有系统审核题，而不是无提示混用。

## 7. 保存结构与接口边界

新增独立、版本化的知识库数据表，保留现有账号、关联、学习进度和报告表。逻辑对象包括：

| 对象 | 关键内容 |
| --- | --- |
| 私有文件 | 所属教师、类型、摘要、大小、存储标识、归档状态 |
| 处理任务 | 文件／生成请求、阶段、进度、错误、重试和幂等标识 |
| 教材与章节版本 | 年级版本学期、章节顺序、来源范围、知识点与审核状态 |
| 题目与版本 | 结构化题目、配图引用、范围、难度、答案解析、审核状态 |
| 生成来源 | 参考题版本、教材片段版本、模型元信息、检查结果 |
| 题组与审核事件 | 用途、组成题目版本、范围快照、审核者、修订时间 |

所有所有权由登录会话确定，不接受客户端任意 owner_id。管理员现有角色可使用自身知识库，不因管理员身份默认公开所有教师资源。

拟定教师接口前缀 `/teacher/knowledge`，分 files、jobs、textbooks、chapters、questions、generations、question-sets 资源；前端通过同源受控代理调用。上传、编辑、审核、归档和生成使用写请求，读取请求不能触发迁移、生成或发布。

文件预览、图片和下载必须再次校验所有权，响应 private/no-store；不放入公开教材静态目录。未授权对象返回不暴露其存在的信息。学生端不能调用教师资源接口。

任务持久化且可恢复，教师最多 2 个并行任务，单次生成最多 50 题。调用模型不占用数据库事务；重试保留人工修订，以任务幂等标识避免重复入库。并发编辑采用版本检查，冲突时提示重新读取。取消任务阻止后续工作，不承诺已发出的模型请求退款。

## 8. 迁移、验证与交付

数据库变更需先在隔离副本演练，再使用一致性备份执行可重复的显式迁移。不在页面读取时偷偷建表，不重置账号、不修改真实学习记录，不自动提交 Git。若实施中发现需要新依赖，另行说明用途、替代方案和影响并征求同意。

第一阶段验收：

1. 教师导航进入知识库，题库／教材切换、搜索、分页和手机布局可用；普通学生不能进入。
2. PDF、DOCX、图片真实上传并核对保存，刷新后记录存在；旧 DOC、损坏文件、超限文件和空白识别有明确反馈。
3. 多个章节文件组成一本教材；未核对章节不能充当生成范围；原有教材页面不被破坏。
4. 手动录题与导入题可审核、归档和恢复；版本修订不覆盖历史来源。
5. 有题库变式、原题题组、混合、空库教材补题分别验证；题量不足不偷换来源，服务不可用不伪报成功。
6. 错答案、缺图、图文冲突、未知范围、越级知识、伪来源样本被阻止审核或明确退回核对。
7. 两个教师的列表、原文件、图片、生成任务和题组严格隔离；学生不能通过接口读取答案。
8. 失败重试、并发编辑、重复请求、取消任务以及重启后的任务恢复可验证，保留人工内容。
9. 单元／接口测试、类型检查、构建和教师／学生身份浏览器验收；自动测试使用临时数据，不污染真实账号。

第二阶段另行按既有测试设计验收发布、作答、批阅、答案释放、正式错题收集和解除关联处理。未完成这些验收前，界面不得显示虚假的“已发送给学生”或“已加入每日练习”。
