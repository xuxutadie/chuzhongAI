# 错题集与分层复习设计

状态：用户于 2026-09-25 明确回复“符合”，书面设计已确认；进入实施计划阶段，尚未实施或修改数据库。

## 1. 用户目标与范围

学生不必再次上传系统里做错的题，也不必自己判断下一步去哪个模块。统一入口名为“错题集”，收纳系统测评、数学练习、拍照上传和手动录入的题目，沿着“理解原题 → 同类变式 → 拓展应用 → 可选挑战 → 间隔复习”逐步学习。

已确认的要求：自动收集系统错题、保留已有上传题、AI 按题型特点整理、理解后再重练、提供拓展和拔高、衔接每日任务、不覆盖原答题记录与分数。

最近逐项确认的规则：学习首页第一步必须是“课堂诊断”，不是“学一学”；五步从首次进入首页时就全部展示，完成并保存前一步后才解锁后一步。系统错题在首次可信判错时收录，不等第四步巩固结束；巩固只追加学习记录并更新状态。入学测评仍保持交卷后收录，避免提前泄题。

实施分两批验收：

1. 统一错题集、可信自动收集、历史补收、来源与状态展示。
2. 基于真实作答的 AI 整理、经过校验的分层练习、复习进度与每日指引。

第二批完成前不把静态占位按钮描述成可用的 AI 练习。保持数学单科范围，不恢复语文英语入口；不改现有测评评分或课堂任务的过关门槛。不在本次顺带重做整个课程排课系统。

## 3. 学生界面

### 3.1 列表

保留 `/wrong-questions` 路由，导航、标题、提示文字改为“错题集”。已有链接继续有效。

页面主行动为“继续今天的错题复习”；拍照、选择图片、手动录入作为“添加错题”的次级入口。列表支持按来源、知识点、学习状态筛选，分页统计由服务端计算，不用当前页数量冒充总数。

每张卡片显示题干摘要、小图、来源、最近错答日期、累计错答次数、当前阶段及一个下一步按钮。图片保留受保护资源地址。系统几何图保留结构化图元，不截图替代。AI 归类不改变原题身份。

### 3.2 单题路线

进入后显示“你当时怎么答的”和原题，主按钮只指向当前阶段。提交本轮答案前不展示本轮答案与解析；已结束的原题允许查看参考解法。

状态分别记录，不用单一“已完成”混淆：

- 待核实：没有可核验作答、原题答案存疑或资料不全。
- 待理解：已收录，尚未通过理解检查。
- 变式巩固：验证同一知识点的迁移。
- 拓展应用：增加条件或改变表达情境。
- 待复习：已完成基础巩固，等待间隔复习。
- 阶段掌握：满足本设计的复习条件，并保留继续练习入口。

“挑战”是独立可选分支，挑战答错不抹去已经通过的基础学习记录；若答案证据确实暴露同一基础缺口，再推荐回到相应讲解。一次答对或点击“我看懂了”都不直接记为掌握。

巩固后仍答错，追加错答记录并安排复习；本次答对，记录“本次订正通过”，不直接判为掌握；达到间隔复习条件后显示“阶段掌握”。所有情况下原题、上传图片、原始错答和后续练习记录都保留，不因订正通过或掌握而自动删除。学生主动删除仍走明确的删除确认，不与学习状态变更混用。

## 4. 可信收集与去重

### 4.1 收集时机

- 入学测评：交卷后根据冻结试卷与已保存答案收集；交卷前不公开答案，也不提前在错题集中泄露判分。
- 日常数学练习：每次学生确认提交答案时发送带稳定事件编号的作答事件，不等全部过关。服务端加载已分配的题目快照核验答案，拒绝客户端自报分数、正确性和参考答案。
- 互动课件即时挑战：有服务端可解析的稳定题号、题目与答案映射时接入；只有“课件完成”消息的课件不能伪造错答记录。为数学正式课件补全可核验映射后再纳入收集覆盖清单。
- 上传/手动录入：仍须学生确认题干；可补充自己的答案与步骤。缺少答案依据时先保存为待核实，不让 AI 猜测替代事实。

入学测评中的未作答进入“待补测”提示，不增加错答次数，不推断为不会。练习主动跳过同样不记错。已有错题条目可以显示其后续跳过事件，但不会因此降级。

### 4.2 身份与次数

- 同一次提交重试采用相同事件编号，唯一约束防止重复计数。
- 系统原题按当前账号、题库题号、内容版本确定身份；仅选项顺序改变时保持同题，但每次事件保存当时的选项与所选内容。
- 题干、已知参数、图形或答案修订后视为新内容版本，关联旧题但不覆盖旧快照。
- 同一道题再次做错：新增作答事件、增加次数，保留一张主卡片。
- 变式题通过母题关联，不因改了数字就和原题合并；优先在母题学习记录下呈现，避免列表无限膨胀。
- 上传题仅在相同确认请求重试时自动去重；文字近似只能提示“可能重复”，不能擅自合并。

## 5. 历史补收及数据保护

提供当前账号专属“补收历史错题”操作。首次打开错题集可提示并启动已获授权的补收，页面显示已补收、已存在、待核实数量。每批最多处理 200 个事件，返回游标，可继续或中断恢复；失败后重试不会重复导入。GET 查询不执行数据迁移或计费 AI 请求。

已交卷入学测评按冻结证据补收，可精确恢复原题、当时选项、答案与配图。历史 `mathSessions` 只能处理仍保留的记录：服务端重新查题判分，保留“历史草稿恢复”来源。能找回作答但无法核验题目或参考答案的条目进入待核实，不用于掌握率统计；没有留下的数据明确提示无法恢复，不捏造历史轮次。

补收不触发批量付费 AI 分析，不重算已发布报告，不改分数，不改完成日期，不影响原有错题图片。删除或归档过的系统来源不得在下次补收时悄悄复活，保留来源抑制标记。

数据库迁移采用增量表和索引，已有 `wrong_questions` 的整数编号与图片关系保持不变。迁移前创建可恢复备份，在临时副本上检查旧记录数量、图片引用、账号边界。生产执行迁移与补收需按明确范围执行，不在启动服务时扫描并修改所有账号。

## 6. AI 整理与出题边界

### 6.1 分析依据

发送最小必要教学信息：题目、选项、结构化配图、已核验参考答案、学生实际答案、可选步骤、相关错答事件。默认不发送姓名、账号、其他同学记录；OCR 后以已确认内容为准。

结构化输出包括知识点、题型、解题方法、已观察事实、可能错因、支持该判断的作答依据、需要确认的问题、分步提示与下一步建议。缺少过程时将原因标为“待确认”，先问一个针对性问题，不把选择题答案直接等同于“粗心”“能力差”等判断。

每份分析关联题目版本和作答证据版本。新增错答或修改确认内容后，旧分析保留但标记过期；不能复用不相符的缓存。

### 6.2 分层练习

1. 理解检查：一个关键概念或步骤问题，经服务端核验通过后进入变式；仅自述“看懂了”不算通过。
2. 变式巩固：连续两道不同参数的同类题首次提交正确，进入拓展；查看提示后的正确记录为“借助提示完成”，仍需一道独立题确认。
3. 拓展应用：至少一道经核验的改变情境或组合条件题独立正确，进入待复习。
4. 拔高挑战：通过变式后可自愿尝试，不强制计入当天基础任务。

连续两次在同一阶段出错时暂停加题，返回相关讲解、让学生说明卡点并建议休息或求助。不能为了凑齐题量持续生成。

### 6.3 题目质量

模型提出教学变式，正式投放前必须通过结构校验、参数边界、唯一答案核验及题图语义一致性检查。数学真值由可复算的模板或校验器确定，不把“第二次问模型得到相同答案”视为证明。

第一版只投放已覆盖确定性校验的六升七和已登记七年级数学题型。模型可选择/调整受限模板参数与教学情境；公式、数值和图形由同一参数生成。尚无校验器的开放性题、复杂证明或无法判定的上传题保留分析与教师确认提示，不自动判分、不伪装已支持拔高。

正确答案与解析留在服务端，提交后才按当前练习记录返回。模型不能生成执行代码、任意 HTML/SVG 或外部资源地址。题目有歧义、题图不符或答案不唯一时拒绝投放；若学生报告已投放题有问题，冻结该练习的自动晋级，原有记录保留。

### 6.4 失败与费用

沿用当前学生对应的个人或教师 AI 服务配置与限流，不改密钥配置。优先生成当天实际需要的分析与一道下一步练习，不预生成整套无限题库。历史补收与列表浏览不计费。

后台工作采用数据库持久化状态，记录请求版本、执行租约、尝试次数和失败原因；短事务领取任务，释放事务后调用模型，完成后校验版本再提交结果。前端可恢复轮询，不依赖网页关闭前的请求一定完成。过期租约允许重领，总共最多尝试两次；达到次数后明确提示手动重试，避免重复消耗。

AI 未配置或失败时保留所有错题与进度，有匹配审核题则提供规则讲解/练习并清晰注明；没有可用题时显示“该题型暂不可自动出题”，不提供虚构结果。

## 7. 每日节奏与复习

### 7.1 首页五步引导（用户最新要求）

用户已明确：学习首页同时展示第一至第五步，文案简短，学生点击“开始”即可进入；前一步完成后才能进入下一步。本条替代仅在首页增加一个错题复习入口的早期方案。以下为用户澄清后确认的五步顺序，功能仍尚未上线：

| 步骤 | 首页标题 | 初次进入时的按钮/状态 |
| --- | --- | --- |
| 第一步 | 课堂诊断 | 开始 |
| 第二步 | 针对学习 | 完成第一步后解锁 |
| 第三步 | 过关测试 | 完成第二步后解锁 |
| 第四步 | 错题巩固 | 完成第三步后解锁 |
| 第五步 | 今日总结 | 完成第四步后解锁 |

“课堂诊断”先测出今天内容的掌握情况，完成条件是规定诊断题已提交并核验，不要求先全答对才能看到薄弱点；“针对学习”承接诊断后安排的讲解与互动；“过关测试”承接学习后的核验；“错题巩固”承接本次错误与当天安排的复习；“今日总结”呈现当天真实完成记录。首页不展开后台模块名、题型分类或复杂路径；错题的理解、变式、拓展仍在第四步内部逐步引导，不把完整长期复习周期塞进一天。

- 五步始终可见，当前步突出一个“开始”或“继续”按钮；未来步骤不可开始，但显示解锁原因。
- 完成状态以服务端核验并成功保存为准，点击按钮或浏览页面不算完成。直接访问后续链接也须校验前序状态。
- 完成当前步后显示“已完成，进入第 N 步”，直接进入对应内容，无需回目录寻找；回到首页时高亮新的当前步。
- 已完成步骤允许回看，不重复记分、计奖或覆盖原证据。刷新与中断续学恢复当前学习日的实际状态。
- 系统确认当天没有需要巩固的错题时，第四步显示“无需订正”，并按服务端判定解锁总结；学生不能自行跳过已有待处理内容。
- 保存失败时保留本步内容并提供重试；当天基础流程完成后明确提示“今天完成了”，拔高挑战单列为可选学习，不锁住每日完成状态。

这五步需要统一映射已有课堂流程与错题复习状态，不仅是五个跳转按钮。实施计划必须先列清现有活动归属与核验证据，不凭展示序号创造新过关条件。原有评分标准和成长值规则不变。

特别区分：首页第一步的诊断阶段完成，不等于现有后端整项数学任务已经过关。原有数学任务的最终过关要求继续在第三步核验，第一步不得被旧的整项任务过关条件锁住。需要新增每日路线阶段记录，不能用同一个整项任务布尔状态伪装五步进度。

### 7.2 错题数量与间隔复习

以下是供审阅的产品默认值，不代表教育测量标准：

- 每天按学生填写的学习时长安排最多 1-3 组错题，组数为 `min(3, max(1, floor(每日分钟数 / 10)))`；未填写时默认 2 组。显示“预计用时”，不保证每个学生用时一致。
- 优先到期复习，其次反复出错，再次新错题；同优先级按最近应复习时间、条目编号稳定排序。
- 当日巩固列表在首次进入第四步或主动开始当天错题复习时生成并固定，纳入当时已有的本次错题和到期复习，不因刷新或之后新收错题不断加量；后续新题进入下一次计划。学生可明确选择额外练习。
- 一组是母题的当前学习阶段，不要求一天内完成理解、变式、拓展和挑战全部阶段。保存后给出“继续下一步”或“今天先到这里”。
- 基础巩固通过后安排次日复习；通过后间隔 3 天，再通过后间隔 7 天。三次不同日期的独立复习通过才显示“阶段掌握”。这些状态不改原测评成绩。
- 复习失败回到相应讲解，并在下一日重新安排，不清空历史。错过日期不惩罚、不把积压全塞到同一天。
- 统一以 Asia/Shanghai 学习日划分；使用标准库日期工具，不依赖浏览器任意本地时区。

错题复习接入首页五步中的“错题巩固”，错题集仍保留独立查看入口。复习阶段采用自己的已保存完成证据，不以跳转页面冒充完成。首版不新增成长值奖励，避免重复计奖。

## 8. 数据与服务边界

计划新增以下逻辑表；具体迁移语句在实施计划中列出并测试：

| 表 | 主要用途与约束 |
| --- | --- |
| `question_answer_events` | 账号、稳定来源事件键、题目版本、原题与选项快照、学生答案、可信判分、来源时间；账号与事件键唯一 |
| `wrong_question_learning` | 与原错题一对一的系统题身份、母题关联、学习阶段、到期日、复习计数、版本号、归档/补收抑制标记；系统身份在账号内唯一 |
| `wrong_question_event_links` | 错题关联各次作答证据；同一事件仅关联一次，允许事件记录“已识别但用户不再收录” |
| `wrong_question_ai_jobs` | 分析/生成任务、依据版本、状态、租约、尝试次数、模型元数据、验证后的结果；同账号同依据同类型请求幂等 |

第一批：

- 当前测评的错答题能够补收，报告分数和 PDF 数据不变；重复补收数量不增加。

- 未作答不计错；不完整历史记录有明确待核实状态。

- AI 输入含实际答案但无无关身份信息；缺少依据不会输出确定性错因。

- 服务端无法被客户端自报掌握状态或参考答案绕过；重复提交不重复推进。
- 页面始终提供一个明确的下一步；断网、刷新、跨日、AI 失败和恢复不丢进度。
