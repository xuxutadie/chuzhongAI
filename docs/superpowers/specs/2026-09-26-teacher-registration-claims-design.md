# 教师注册、学生认领与学情查看设计

状态：待用户审阅；仅为设计，尚未修改业务代码或数据库。

## 一、目标与已经确认的方向

用户需要教师自行注册；学生填写学校、年级和班级；教师关联自己的学生后查看具体学习情况。用户已同意采用“学生提供认领码，教师输入后关联”。

学生路径：完善资料 → 在学习档案生成认领码 → 交给指定老师 → 可查看和解除关联。

教师路径：教师注册 → 引导认领学生 → 我的学生 → 学生学情详情。

本基础阶段只做这条完整流程，保留已有账号、访谈、测评、报告、错题及今日任务。不会把学校、班级文字匹配当作访问授权。用户随后追加的题库、智能组卷和测试发布作为下一阶段，详见同目录 `2026-09-26-teacher-question-bank-exams-design.md`，两份方案需一并审阅。

## 二、现有代码约束

- 登录页已有账号登录、学生注册和一次性教师初始化。
- 现有教师管理使用 `admin` 身份；`users.role` 的 SQLite 约束尚不包含 `teacher`。
- 学生名单和重置密码依赖 `users.created_by`。该字段还决定个人/托管 AI 服务模式，不能通过改写它来认领学生。
- 学习档案在 `diagnosis_profiles.fields_json` 中，带版本号与访谈确认状态；测评另存当时的资料快照。
- 诊断、今日学习路线、错题及 PDF 接口当前均以学生本人为访问边界。
- 新功能沿用现有登录会话、前端代理、账号切换保护、SQLite 和图表/PDF能力；不新增依赖。

主要关联文件：`frontend/app/login/page.tsx`、`frontend/app/teacher/students/page.tsx`、`frontend/app/profile/page.tsx`、`frontend/app/diagnosis/`、`shared/diagnosis-interview.json`、`backend/app/schemas/student_workspace.py`、`backend/app/services/student_workspace_service.py`、`backend/app/repositories/student_workspace_repository.py`、`backend/app/services/transition_diagnosis.py`。

## 三、教师注册与身份边界

### 页面

登录页固定显示“账号登录 / 学生注册 / 教师注册”。首次初始化仍只在系统未初始化时显示，名称与普通教师注册区分。

教师注册填写：教师姓名、学校全称、任教年级与班级（可多个）、账号、密码及确认密码。不收集身份证、家庭住址等无关信息。学校信息属于自行填写，不展示“学校已认证”等无依据标识。

注册成功进入教师学生管理页，以“认领第一位学生”为首要操作。即使登录链接携带学生端 next 参数，也应送入其有权限的教师页面，不发生跳转循环。

### 权限

- 新注册账号固定为独立 `teacher` 角色；请求不得指定 `admin`、其他学生归属或权限。
- 现有 `admin` 保留原有创建学生、批量开通、重置其创建学生密码、查看服务器 AI 配置状态等能力。
- 普通教师在本基础阶段获得认领、解除自己的关联及查看已关联学生学情的权限，不获得管理员操作和服务器配置读取权限。后续题库测试阶段额外允许管理个人题库、发布及批阅自己的测试，不扩大为修改既有学生成绩的通用权限。
- 不复用旧接口中客户端提供的角色请求头作为授权；所有新接口从服务端会话确认角色和身份。
- 账号唯一性、密码加密、登录限流沿用现有机制，公开教师注册增加速率限制。注册不代表学校身份认证，取得学生认领码才建立具体学情访问授权。

## 四、学生学校和班级资料

- 在现有机器人逐问逐答流程中加入学校与班级问题，沿用已有年级字段；资料编辑页同步支持修改。
- 当前学习档案作为学校、班级、年级展示的统一来源，教师端不另外维护一套可冲突的学生资料。
- 学校全称上限 100 字、班级上限 40 字，去除首尾空白；年级沿用现有限制。文本只用于展示和在已授权名单内筛选。
- 新学生确认访谈时校验学校和班级；尚未入学或分班的学生可明确选择“暂未入学 / 待分班”，不要求编造资料。
- 已确认访谈的老学生在首页与学习档案获得“补充学校和班级”提示，独立保存缺失字段，不重置访谈确认状态，不重新做测评、不阻断已有学习。
- 补填和编辑使用档案版本号避免多个页面互相覆盖；旧客户端未传新字段时保留已存值。
- 修改学校或班级不会自动撤销或新增师生关联；旧测评报告保留原始快照，教师详情单独显示当前资料。
- 学校、班级不加入发给大模型的访谈上下文，不影响出题和评分规则。

## 五、认领码与关联规则

### 推荐默认规则（随本文一并审阅）

- 学生在“学习档案 → 我的老师”主动生成认领码，生成前说明：持码教师可查看基本学习资料、已提交测评、学习进度、错题与报告。
- 使用安全随机的 12 位易辨识字母数字码，分组显示；有效期 30 分钟，单次使用。一次只保留一个有效码；重新生成使旧码失效。
- 码只在生成响应中展示，数据库只存哈希；不写入 URL、日志或浏览器持久缓存。离开页面后可以重新生成。
- 教师提交码即建立关联；不增加一次学生审批，因为主动交码已经是本流程的授权动作。
- 可关联多位教师，但必须对每位教师单独生成并提供新码；教师之间不能转授访问权。
- 同一教师、学生只存在一条有效关联。重复请求不重复创建；同一请求的网络重试返回原收据，不给其他教师重放使用。
- 学生和教师均可解除双方关联。解除后所有学情、题目图片及 PDF 接口立即失去权限；已下载文件无法从他人设备追回，授权提示中应说明。
- 学生可以在“我的老师”查看教师姓名、自填学校、关联时间并解除关联。关联记录注明“认领码授权”，不是实名认证。

### 防止误认领与越权

- 输入码时不提供“通过学校搜索所有学生”的入口，也不列出任何未关联学生。
- 使用码后清楚显示所关联学生的称呼、学校和班级；发现不符可立即解除。
- 无效、过期、已被他人使用的码统一提示“认领码无效或已失效，请学生重新生成”，不泄露码背后的账号。
- 每个教师每 10 分钟最多尝试 10 次认领；码生成每个学生每小时最多 10 次；服务端记录计数并返回 429 与重试提示。前端限制不能代替服务端限制。
- 在同一事务内验证有效期、消费码并创建关联，确保并发认领最多成功一次。
- 认领不改 `created_by`，不切换学生个人/托管 AI 模式，不授予密码重置、代答、删错题、修改既有测评成绩和学生资料权限。后续教师发布测试的正式批阅及改判仅限其自身测试，并必须保留审计记录。

## 六、教师工作台与学生详情

### 我的学生

顶部提供“认领学生”，下方按已授权学生的学校、年级、班级筛选。名单显示称呼、学校班级、最近一次已记录学习活动、当前学习状态；不以登录行为冒充学习活动。

没有学生时展示认领步骤；筛选无结果、读取失败和加载中分别有清晰状态。普通教师不显示管理员专用按钮。

### 学生详情

| 区域 | 展示内容 | 约束 |
| --- | --- | --- |
| 基本学习资料 | 称呼、学校、年级、班级、教材、学生自述目标与成绩 | 自述成绩明确标识，不当作系统测评分数 |
| 学习概览 | 最近已提交测评、薄弱知识点、最近活动 | 无数据不填 0 分或推断“能力差” |
| 每日学习 | 当天五步状态、近 7 天已有记录 | 只读，不自动创建或推进路线 |
| 测评记录 | 已提交测评列表、逐题作答与解析、已有维度图表 | 进行中的测评仅展示状态，不暴露未提交答案或标准答案 |
| 错题与巩固 | 题干、学生错答、来源、知识点、阶段、重做记录与已有分析 | 只读，不触发 AI 分析或自动补收；原图使用独立授权接口 |
| 诊断报告 | 网页报告和现有 PDF 下载 | 校验报告归属；无报告显示尚未完成，不自动生成新诊断 |

详情按区域逐步加载，长列表分页，显示记录时间与数据来源。教师查看不调用收费大模型，不增添学生学习行为。

视觉沿用当前蓝、绿、橙配色：蓝色主操作、绿色完成状态、橙色待关注项；状态同时使用文字。桌面显示信息分区，手机按单列排列；按钮可键盘访问。

## 七、数据结构与兼容迁移

新增专用仓储/服务，避免把师生关系继续塞进现有大型学生工作台服务。

拟增加：

1. `teacher_profiles`：教师 user_id、学校、任教班级 JSON、更新时间。
2. `teacher_student_links`：teacher_id、student_id、来源（认领/历史创建）、有效状态、关联与解除时间；同一师生组合唯一。
3. `student_claim_codes`：码哈希、学生、过期/消费/撤销时间、消费教师、请求收据标识。不保存明文码。
4. 专用操作记录：注册/生成/认领/解除所需的限流和最小审计字段；复用现有表前先确认其支持用途，不混用登录失败统计。
5. 幂等迁移版本记录；学生学校班级使用既有档案 JSON 增量字段，无需建立学校、班级管理系统。

`users.role` 增加 teacher 会涉及 SQLite CHECK 约束迁移，不能简单写入新字符串。实施时须先在数据库副本验证保留主键、外键、索引、账号密码哈希和会话，检查行数及 `foreign_key_check`。迁移失败应整体回滚，不能遗留半张用户表。

在已获实施许可后，用 SQLite 一致性备份机制备份正式数据库，不能只复制可能处于 WAL 模式的主文件。短暂停写完成迁移，记录备份位置。先部署兼容新角色的服务，再开放注册入口；结构迁移不放进每次请求的仓储构造函数。

现有管理员创建的学生回填为“历史创建”有效关联，保持原管理范围，不扩展为管理员可查看所有自主注册学生。保留原 `created_by` 和原密码管理规则；解除学情关联不等于撤销原有管理员账号维护权限，界面需区分两者。

迁移不得创建虚构学校班级、重置账号、删除成绩、重算报告或改变 AI 费用归属。回退应用和恢复数据库必须成套处理；已有新作答时不得直接覆盖旧备份，应先保全新增数据。

## 八、接口与访问边界

以下为拟定新增接口，尚未实现；前端继续通过同源代理访问后端。

- `POST /auth/register-teacher`：固定教师身份注册，返回现有会话响应结构。
- `GET /teacher/profile`、`PUT /teacher/profile`：当前教师的学校和任教班级。
- `POST /me/teacher-links/code`：学生生成码，响应 no-store。
- `GET /me/teacher-links`、`DELETE /me/teacher-links/{link_id}`：学生查看及解除自己的关联。
- `POST /teacher/claims`：提交码及请求编号，返回认领收据。
- `GET /teacher/linked-students`：教师已授权学生分页列表，避免破坏原有管理员学生名单接口。
- `DELETE /teacher/links/{link_id}`：教师解除自己的关联。
- `GET /teacher/students/{student_id}/overview`、`/learning-history`、`/assessments`、`/wrong-questions`：学情分区。
- `GET /teacher/students/{student_id}/assessments/{attempt_id}`、`/assessments/{attempt_id}/pdf`、`/wrong-questions/{question_id}`、`/wrong-questions/{question_id}/image`：受保护明细。

每个资源请求同时校验真实教师会话、当前有效师生关系、目标记录实际 student_id，不能只依赖列表页或 URL 参数。无权访问和不存在的学生资源统一返回 404。缺少登录返回 401，不符角色返回 403，版本/并发冲突返回 409，字段错误返回 422，限流返回 429。

详情与 PDF 使用 private/no-store，解除关联后不能依赖过期缓存继续下载。服务器响应采用字段白名单，不返回整个工作台状态、密码哈希、令牌、API 密钥或无关聊天。前端账号切换时取消旧请求并清空教师学情缓存。

## 九、验证与验收条件

先在临时数据库与测试账号中验证，再在实际界面验收；不得通过真实学生交卷来测试。

- 登录页教师入口始终可见；新教师注册后只有 teacher 权限，学生和教师 next 跳转正确。
- 新旧账号均可登录，原教师创建/批量开通/密码管理范围不变。
- 新学生逐问填写学校班级；旧学生补填后测评、确认状态、报告、错题和今日任务不变。
- 有效码成功、过期失效、换码失效、重复请求幂等、并发消费唯一、限流生效；码未进入日志和持久缓存。
- 两位教师对同一学生的访问必须分别授权；改变学校/班级不能获得访问权；解除后详情、原图和 PDF 均拒绝访问。
- 认领和详情查询前后，对 created_by、AI 模式、每日路线、测评答案、错题状态做数据比对，确保只改变授权关系。
- 进行中的测评不泄露题目答案；无记录和服务故障不显示伪造统计。
- 迁移在副本中重复执行安全、失败可回滚、外键完整、账号和学习数据行数一致。
- 完整前后端测试、类型检查、隔离构建通过；已登录教师和学生两个身份验收，覆盖 320/768/1440 像素、键盘操作及加载/错误/空态。
