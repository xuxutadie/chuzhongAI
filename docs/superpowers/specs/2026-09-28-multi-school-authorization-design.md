# 多学校数据隔离与学生授权设计

日期：2026-09-28  
状态：用户已确认本书面设计并要求直接实施。实施进度见同日期的实施计划；线上启用须单独通过迁移与验收门槛。

## 1. 目标与已确认原则

产品面向多所学校、培训机构及独立学生。统一账号登录，学习记录跟随学生；教学资源按学校或机构隔离，教师凭学生授权查看学情。

用户已明确确认：

1. 学校与培训机构按同一种独立教学空间管理，彼此不能自动访问资源。
2. 教师只能查看已授权学生的记录；同校、同班、创建账号或担任学校管理员，本身均不构成学情查看授权。
3. 获授权教师可查看该学生全部历史学习记录，不受记录产生的学校／机构限制。
4. 授权面向具体教师，不扩散给教师的同事或学校。
5. 历史学情默认只读，教师不得代改历史答案、分数或删除学习记录。
6. 学生可撤销授权；之后停止在线访问，已下载文件无法远程收回。
7. 平台管理员保留经审计的全站管理能力。现有指定管理员账号、原密码和历史数据保留。

“全部历史”指读取时已经形成的记录，因此有效授权也覆盖授权后新产生的学习记录；不包含未交卷答案、私人凭证或教师原始资源库。授权确认页必须说明这一点。

## 2. 与完整上线工作的关系

上线工程分为四个可独立验收的子项目：

| 子项目 | 交付内容 | 启用条件 |
| --- | --- | --- |
| 安全与部署基础 | 依赖修复、正式运行配置、密钥存储、HTTPS、日志告警与备份恢复 | 安全审计及恢复演练通过 |
| 多学校隔离与授权（本文） | 教学空间、成员、授权、资源与后台任务隔离、旧数据迁移 | 跨校越权与撤销测试、迁移核对通过 |
| 教师发卷闭环 | 审核题组、发布、学生作答、批改、错题归集与教师反馈 | 使用本文身份边界；独立设计与业务验收 |
| 上线验收与试点 | 三端浏览器、真实 AI/OCR、容量与故障演练、数据使用告知 | 前述子项目通过，明确首发规模和运行环境 |

本文只定义第二个子项目，不把它的完成等同于整个产品上线。前次审计发现的依赖严重告警是对外开放前的阻塞项；依赖变更方案需列明版本、原因、替代方案及兼容性风险后确认，不在本文中擅自安装。

## 3. 架构选择及取舍

采用已确认的“统一平台、学生统一账号、学校资源隔离、教师逐人授权”方案。

- 不采用每校完全独立部署：学生跨校授权需要重复账号或额外同步，维护与撤销一致性成本较高。
- 不采用仅按学校名称筛选：名称可重复、可自行修改，不能作为权限依据。
- 采用不可变空间 ID 和后端权限校验：空间成员关系与学生授权是两个独立条件，均由服务端读取真实会话后验证。

本阶段沿用现有数据库引擎，不在同一变更中搬迁数据库。隔离契约不依赖前端或单个数据库实现；正式服务器选择、密钥迁移及并发容量在部署子项目中验收，不据此承诺当前单进程部署能承载多校流量。

## 4. 身份、空间与权限

### 4.1 身份模型

- `users` 保持平台统一身份，不为学生在每个学校复制账号。
- `education_spaces` 表示学校、培训机构或独立教学空间，拥有独立 ID、名称、类型、状态和修订号。
- `education_memberships` 表示账号在某空间的身份：学校管理员、教师或学生。学校管理员不是全站 `admin`。
- 一个账号可以存在多个成员关系；每次教学操作只在一个明确的当前空间内执行。学校切换不会转移个人学习记录。
- 独立学生无需加入任何空间即可继续个人学习。公开填写学校、班级只是自述资料，不自动建立成员关系。

### 4.2 权限边界

| 身份 | 允许 | 不允许 |
| --- | --- | --- |
| 平台管理员 | 管理空间、全站账号；经审计查看学情和资源 | 无审计模拟学生作答、回显密码或私有密钥 |
| 学校管理员 | 管理本空间成员与角色、撤销成员资格 | 修改全站身份／密码、停用他校成员账号、默认查看学生全部学情 |
| 教师 | 管理当前空间内自己的教学资源；查看明确授权学生的全部历史学情 | 查看同事私有题库、通过学校身份批量获取未授权学生 |
| 学生 | 个人学习、查看自身记录、确认与撤销教师授权 | 读取其他学生数据、靠修改空间 ID 获得教师权限 |

本期保留知识库既有“教师私有”边界，并增加空间边界，即同时核验空间和所属教师。不会借学校隔离改造自动开放校内共享题库；校内共享如需要，另行设计发布权限。

平台管理员进入自己的教师工作区同样选择空间；跨空间管理走专用管理接口，普通教师接口不得因为管理员身份而隐式混合资源。

### 4.3 空间开通与成员加入

首版采用平台管理员开通／审核学校或机构，并指定学校管理员的方式，不允许自填学校名称就占用学校身份。学校管理员可以向已存在的账号发出空间邀请，账号接受后加入；邀请不能授予全站管理员。

教师公开注册保留，但未加入已开通空间时只能完成账号资料与查看待处理邀请，不能认领学生或访问学校资源。独立执教者可申请独立教学空间，由平台管理员开通。成员邀请只保留摘要、有效期、目标账号、空间及角色；单次消费，不能用邀请扩大到其他空间。

加入空间、加入班级和接受教师授权分别呈现，禁止捆绑为一次不明确的确认。学校管理员可管理成员名册基础信息，但不因此取得成绩、错题或报告访问权。

## 5. 学生授权流程

### 5.1 新授权

1. 教师在当前空间发起授权邀请，服务端固定教师 ID 和成员关系 ID。
2. 学生登录后打开邀请，页面展示教师姓名、学校／机构，以及“允许此教师查看全部历史和授权有效期间新增的学习记录，包括报告和错题；不允许修改”的说明。
3. 学生明确确认后，在同一事务创建授权并记录审计。持有码者不能仅凭邀请码替学生确认。
4. 教师只能在该邀请所属的有效成员身份下使用授权；学校或教师成员被停用后不可继续使用。
5. 学生在“授权管理”中查看教师、机构、范围、授权时间，并可单独撤销。

授权数据 `education_student_grants` 关联学生账号与教师成员关系，状态包含 active、revoked；范围在本期固定为 `all_learning_history_read`，不接受客户端自定义扩大范围。重复提交使用请求编号和修订号处理，不能复活已撤销授权。

旧“学生给码、教师直接认领”入口在新边界启用后必须接入明确确认流程，不得留作绕过途径。

### 5.2 跨校、转校与撤销

- 教师在甲校获得的授权不能在其乙校身份下使用；需要乙校独立授权。教师离开甲校后，甲校关联授权失效。
- 学生变更自述学校或退出某空间，不删除个人学习记录，也不自动新增或转让授权。界面列出已有授权并允许逐个撤销。
- 教师账号、教师成员或空间被停用时，关联查看立即拒绝，并撤销相关授权；恢复账号或成员资格不自动恢复这些授权，需要学生重新确认。
- 撤销时递增授权修订号；列表、报告、图片和 PDF 均重新校验，后台长任务输出前再次校验。无法撤回已经返回的响应或已下载文件，不做不实承诺。
- 撤销不会删除原始学生记录或修改历史成绩，不把学生转成另一个账号。

## 6. 哪些数据可以跨校看

可读：学生基本学习档案、个人学习进度、已提交测评结果与逐题记录、错题集、已生成报告及对应附件。授权范围内可含在其他机构形成的已提交学习记录。

不可读：其他学生、未交卷答案、教师私有题库原件、未公开试卷与答案库、其他机构管理资料、账单、API 配置及密钥。

历史答卷内的题目和解析使用“交卷时保存的学生作答快照”展示，不据此授权访问出题教师的原题资源地址。教师资源 ID、内部来源路径、未公开答案库链接不得通过历史学情泄露。后续发卷模块须满足这一契约。

授权只用于站内只读展示和已有报告下载，不自动允许将学生全部历史发送给大模型。本期不新增批量导出或跨校 AI 分析入口。

## 7. 后端与资源隔离

### 7.1 权限链

受保护请求按以下顺序处理：有效会话 → 正常账号 → 有效空间 → 有效成员 → 具体操作权限 → 目标记录归属／学生授权。

学生个人学习接口仍只基于自己的身份，不因未加入学校被阻断。跨校读学生历史是明确的授权路径，不等于取消所有查询的空间约束。

所有新增权限集中在统一策略模块，覆盖列表、详情、搜索、统计、附件和后台任务；禁止在单个页面临时拼接判断。客户端传来的空间 ID 只用于选择候选空间，后端必须重新验证成员关系。

敏感写入在写事务取得锁后重验实际会话、角色、成员状态和修订号，与审计原子提交。受限对象返回统一 404，防止通过报错探测别校资源；未登录 401、上下文切换或修订冲突 409、缺失迁移 503，不将失败伪装成空列表。

### 7.2 教学资源和任务

现有知识库的教材、章节版本、题目版本、题组、上传原件、图片、导入／生成任务及其事件都需标注空间归属。保留所属教师字段；父子引用必须同时匹配空间和所有者，不能仅校验顶层列表。

私有下载经后端鉴权提供，不在公开静态目录暴露文件。文件名、上传内容或模型返回值均不能决定空间或磁盘归属。备份和个人密钥目录始终不对网页开放。

后台任务保存创建者、空间、成员修订和所需授权修订。领取、调用外部服务前、写回和输出前均校验当前权限；失效结果不得写入别的空间。已发送给外部供应商的调用不能保证撤回或免计费，界面需如实说明。

缓存键、幂等键、任务去重和资源检索均包含必要的空间／账号／授权上下文，不跨空间复用私有结果。公开课程内容可以共享，但不得混入个人或教师私有资料。

### 7.3 AI 配置与费用边界

不因为学生跨校授权而共享教师密钥或自动改变个人学习费用归属。教师私有配置须结合当前空间和教师身份校验；平台统一服务仅可由平台管理员明确分配给某空间，不能默认让所有新注册教师消耗统一额度。

凭证只在服务端使用，前端只见配置状态；不得将密钥或未授权其他人的记录放入模型上下文。本阶段不更换加密实现，正式服务器迁移由安全与部署子项目提供验证后的方案。

## 8. 页面与操作

- 平台管理台新增“学校／机构”，管理开通、停用及学校管理员；保留现有全站账号管理入口。
- 教师页顶部显示当前学校／机构；多个成员身份时可切换，清空前一空间的数据和未提交资源操作。
- 教师学生列表只展示当前成员身份已获授权的学生，明确“跨校历史记录已获本人授权”。
- 学生账号菜单新增“授权管理”，展示全部有效授权及撤销入口；确认页不预勾选同意，不隐去全部历史范围。
- 学校管理员的成员管理与学生学情分开，不能出现默认“查看全校学生历史”的入口。
- 保留现有多巴胺蓝图风格，不借权限改造重做全站 UI。
- 多标签页请求同时核对当前账号和空间／成员上下文；切换后取消旧请求、丢弃迟到响应，受保护附件亦携带相同上下文。

## 9. 旧数据迁移与兼容

1. 先做只读盘点和一致性备份，覆盖数据库、私有上传资料及加密配置。先在副本演练，不按姓名／学校名称自动合并账号或空间。
2. 生成教师与资源到空间的显式映射清单，由平台管理员核对。无法确认归属的资源保留原件并隔离，禁止默认归入某所学校。
3. 保持用户 ID、密码、个人学习记录、历史报告和错题不变。为知识库及任务增加归属，不改变原题版本与学生成绩。
4. 旧 `teacher_student_links` 和认领码保留为迁移证据；旧关系不能自动当作学生已同意跨校全部历史的新授权。切换后旧码失效，未重新确认的教师暂时看不到学情；学生个人使用不受影响。
5. 现有平台管理员的经审计查看不依赖教师授权；不得因迁移误降权。管理员自己的教师资源也必须明确映射空间。
6. 涉及改表的迁移使用版本号、短事务、失败回滚和一致性校验；完成后验证原业务数据指纹、附件摘要和外键，并撤销不再适用的旧会话／上下文。
7. 写入新数据后不能直接覆盖旧数据库回退。回退优先关闭新入口、保留新数据并修复；恢复备份须停服务并明确会丢失的时间区间，另行确认。

隔离能力采用一次完整切换，不允许部分接口读新授权、部分接口继续读旧关联。未完成映射时不对外启用教师端新流程。

## 10. 验收标准

使用甲校、乙机构、独立教师空间、独立学生及平台管理员的合成账号验证，不拿真实学生记录造测试结果：

1. 同名学校不会共享空间；自行修改学校或班级字段不增加任何权限。
2. 同校未授权教师、学校管理员均不能查看学生学情；获授权的跨校教师可读取该学生全部已形成历史。
3. 一名学生可分别授权不同空间的教师；撤销其中一个不影响其他有效授权，也不删除自身记录。
4. 教师切换空间、离职、账号停用、学校停用后，旧授权和迟到请求不可使用；恢复状态不会复活授权。
5. 列表、详情、搜索、统计、图片、PDF、资源父子引用、任务和缓存均通过跨校 ID 替换测试。
6. 未交卷答案、教师原件、私有密钥与未授权学生不能通过历史学情、错误信息或 AI 上下文泄露。
7. 并发确认／撤销、重复提交、任务执行中撤权、会话撤销和多标签切换均保持一致。
8. 数据副本迁移可重复执行；错误映射拒绝；原账号、原密码、答卷、错题、报告及附件保持一致。
9. 学生、教师、学校管理员、平台管理员在桌面和手机完成真实浏览器验收，并覆盖刷新、断网重试和退出登录。
10. 后端全量测试、前端逻辑测试、类型检查及正式构建通过；真实模型质量与容量验收由整体上线阶段另行记录。
