# 数学衔接诊断：使用与维护

## 学生怎样使用

1. 用学生账号登录。未完成首次建档的学生会进入全屏访谈；教师仍进入学生管理台。
2. 机器人每次呈现一个问题，底部填写或选择回答。12 个基础问题涵盖称呼、年级、教材、学习进度、考试得分与满分、成绩变化、困难、解题习惯、学习感受、目标与时间；按回答最多增加 6 个追问。除称呼、年级和教材外均可跳过；点「发送」才会保存。
3. 核对并确认档案。六年级、升七年级和七年级可以开始 24 题测评；其他年级不使用这份衔接卷作为诊断。
4. 选择答案后点「保存并继续」。可以跳题、返回答题卡、仅保存或保存后退出。再次登录会续答，不需要重新建档。
5. 点「检查并交卷」，确认剩余未答题数后提交。原答案锁定，服务端生成分数、柱状图、饼图、雷达图与建议。
6. 在「诊断报告」下载 PDF：六页诊断主体，加上实际试卷的题图解析、学生自述附录。页数由内容决定。以后复测会生成新记录；历史报告仍可查看。

右上角「我的账号」可进入学习档案与 AI 设置。数学学习页包含互动教学、教材、专项练习和日常任务。

## AI 与固定流程的区别

- 已配置、已启用的账号 AI 会根据教学背景生成访谈衔接语，并为报告补充学习建议；系统的必需问题仍保持可核对，避免漏掉必要字段。
- 教师发放的账号沿用教师服务，自主注册账号沿用自己的服务，不改变费用归属。
- 没有 AI 或调用失败时明确显示固定引导/规则诊断，仍可完整建档、测评并下载 PDF。
- 组卷和判分不依赖即时生成的答案。v2 仍有 30 道原创选择题，每个维度选 4 道，总共 24 道；参考自报成绩与薄弱内容选择入口题/综合题，打乱顺序和选项。每份新试卷有 6 道配图题，包含 4 道几何题、数轴和统计方格图。题图是程序绘制的几何元素，不是 AI 随机生成的图片。
- 数学教材版本是学习背景，不代表本卷覆盖该教材所有章节。当前卷不是标准化心理测量，也不提供班级排名或虚构的历史趋势。
- 每个维度 4 题，一题对应 25 个百分点。未作答单列，在卷面分中计 0，但不能据此断言学生不会。

## 部署

后端安装 `backend/requirements.txt` 中已批准的 ReportLab 依赖；当前开发环境使用 ReportLab 4.5.1。

```powershell
# backend 目录
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# frontend 目录，另一个终端
pnpm dev --hostname 127.0.0.1 --port 3000
```

PDF 优先使用 `backend/assets/fonts/NotoSansSC-Regular.ttf`，Windows 可使用现有 `C:/Windows/Fonts/simhei.ttf`，Linux 可使用 `/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc`。字体必须支持中文和 TrueType 嵌入；不要把 Windows 字体复制到其他机器重新分发。无字体时网页报告仍然可用，下载会给出明确提示。

PDF 使用内存生成，不写公开报告目录；下载必须经过当前学生身份校验，响应禁止缓存。实现依据 [ReportLab 官方字体与绘图说明](https://www.reportlab.com/docs/reportlab-userguide.pdf)。

## 数据与恢复

- SQLite 增加 `diagnosis_profiles` 和 `diagnosis_attempts` 两张独立表，没有删除或改写旧课程、账号、错题、日常学习记录。
- 档案有版本号，多标签页更新冲突时要求重新读取；试卷、当时档案、作答和报告均按学生账号保存。
- v2 新访谈回答存入已有档案 JSON 的 `learning_details`，不新增或变更数据库表。已经确认的旧档案不强制重填，旧试卷不换题、不补图、不改版本；从「独立复测」创建新试卷可体验配图题。
- 交卷后禁止改答，报告解读只能补充文字，不能修改服务端数值。编辑现在的学习档案不会重写历史报告。
- `shared/subject-visibility.json` 控制启用学科；目前只有数学。重新启用语言学科后，其内容和旧记录仍在；五项主导航是本版的独立简化布局，恢复语言入口时还需要明确设计入口位置。
- 旧语言任务不删除，已产生的历史成长值也不抹去。新默认日常任务只创建数学，学生端过滤旧语言任务入口。
- 部署前备份学生 SQLite 文件（运行时使用 SQLite 的一致性备份方式，不只复制可能未合并的主文件）。回退应用版本时可保留新增表，不要求删表。
- 本机 UI 验收使用标为「验收测试同学」的独立账号，不应把该账号的答题数据用于真实学生报告。

## 验证命令

```powershell
# backend
python -m unittest discover -s tests

# frontend
pnpm type-check
node --test tests/*.test.mjs
pnpm build
```

`next dev` 与 `next build` 默认共用 `.next` 输出目录；执行生产构建时应先停止开发服务，构建后再启动，避免并行写入造成临时页面错误。

重点检查：首次登录、逐题保存、退出续答、跨账号隔离、多标签页版本冲突、未答题确认、首次成绩锁定、历史复测、未登录 PDF 拒绝访问、中文字体、零分/全对/全跳题与长字段的 PDF 排版。

## 全屏与访谈隐私

- 对话默认铺满浏览器内容区；「进入全屏」需学生点击，并取决于浏览器支持。历史对话在右上角展开，不随每次问答堆积；AI 设置和隐私说明保留在回答区。
- 动态机器人区分等待、连接思考和保存回应；系统开启减少动态效果时关闭动画。
- 新访谈内容随账号保存。配置 AI 后，教学背景与学习回答用于衔接语和报告建议；昵称、账号和密钥不会主动发送。学生需避免在自由回答中输入隐私信息。
- 分支追问由共享题目定义决定；AI 只润色衔接语与提供建议。没有配置 AI 时明确显示规则引导，不伪装为实时 AI 对话。

## 教师上传题库（待确认格式，尚未上线）

拟采用教师上传、核对题目/答案/图形、确认启用，再用于该教师学生的测评。未上传继续内置题库；上传后按知识点覆盖优先使用教师题目，不足部分需明确提示是否由内置题补齐。原题保留；变式区分选项顺序调整与数值/情境改编，后者必须重新核验答案和图形，不能只改题干。当前还未实现上传入口，需先确定 Excel、Word/PDF 或扫描图片等主要来源，以及新增独立教师题库记录的方案。
