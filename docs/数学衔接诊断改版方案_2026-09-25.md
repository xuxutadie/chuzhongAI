# 数学衔接诊断改版方案

状态：用户已批准范围、诊断数据表与 ReportLab 依赖；按本方案实施并记录验收结果。

## 一、目标与默认范围

把学生首次体验收敛为「全屏 AI 访谈 → 确认学习档案 → 六升七数学衔接测评 → 图表诊断报告与 PDF → 针对性学习」。

- 第一版只做数学。语文、英语入口和推荐任务暂时隐藏，保留原课程与历史数据，便于恢复。
- 以六年级、升七年级、七年级学生为目标。其他年级的账号保留，但不能把这份衔接卷标成适合所有年级的诊断。
- 尚无入学档案的现有学生也进入新流程；已完成的学生不再重复建档，中途退出后可继续。
- 教师仍进入管理台。已有管理员时，登录页隐藏首次设置教师入口。
- 不覆盖原有学习进度、错题或分数，不删除旧文件，不修改现有环境密钥，不自动提交 Git。

## 二、现状与需要补齐的部分

- 前端为 Next.js / React，后端为 FastAPI，学生业务数据使用 SQLite。
- 已有登录、学生身份隔离、个人/教师 AI 配置、数学题库、学习草稿与错题功能。
- 当前日常数学任务要求至少完成指定题量并达到 98 分，不能用于保留首次能力水平的入学诊断。
- 当前报告页主要统计今日任务完成情况，尚无六升七测评、能力图表或诊断 PDF 导出。
- 已登记的可信数学课程主要是北师大版七年级上册，六年级衔接题库需要补充。其他教材版本可以建档，但不能宣称已覆盖其全部课程。

## 三、学生使用流程

### 1. 全屏 AI 访谈

- 使用占满应用视口的对话界面，桌面与手机均适配；隐藏复杂侧栏，保留退出、保存后稍后继续等必要操作。
- 每次问一个问题，结合快捷选项与自由输入，根据已有回答适度追问，避免重复询问。
- 收集：称呼、当前年级、数学教材版本及上下册、最近一次数学考试得分及满分、考试大致时间、薄弱内容、学习目标和可用学习时间。
- 考试分数、考试时间允许选择“不记得/暂不填写”，不收集与教学无关的身份或联系方式。
- 区分已有事实、学生自述与 AI 推测，生成可编辑档案卡供学生确认，确认后再组卷。
- 使用账号已有的 AI 配置；服务不可用时明确提示切换为固定问题引导，不能把固定问答冒充实时 AI。
- 档案与访谈进度按账号保存，跨账号切换和多标签页请求继续遵守既有身份隔离约定。

### 2. 六升七数学衔接测评

- 默认 24 题，参考用时 30—40 分钟，满分折算为 100 分；不以超时自动判零。
- 六个知识维度各 4 题：数与运算、分数与百分数、比与比例、几何与测量、数据与统计、代数初步。
- 约 75% 六年级基础、25% 七年级入门；根据年级、教材与自述调整题目情境和难度，保持维度覆盖与计分规则一致。
- AI 辅助选题和解释，正式题目来自新增的原创、经校验题库；答案和评分在服务端核验，不能直接采用未经核验的临时模型题目。
- 记录试卷版本、每题知识点、难度、权重、作答、是否跳过及用时；支持中途保存和继续。
- 可跳题；交卷前提示未作答数并允许确认提交。首次提交后冻结结果，后续重测另建记录。
- 提交前不透露答案，不使用“练到 98 分才能结束”的日常规则。得分低也能立即生成报告。
- 用时仅作参考，后台挂起或离开页面的时间不用于草率推断能力；不自动认定“粗心”“焦虑”等原因。

### 3. 精美诊断报告与 PDF

- 提供网页报告预览和真正可下载的 PDF 文件，不以截图或“打印网页”冒充直接 PDF 下载。
- 默认 5—6 页 A4：学习概览、六维诊断、作答分布、重点错题与依据、六升七衔接建议、两周学习计划。
- 柱状图：六个知识维度的本次得分率，同时显示对应题数。
- 饼图/环形图：答对、答错、未作答题数分布，明确分母和占比。
- 雷达图（用户所说的网状图）：展示六维本次测评表现，固定 0—100 刻度；与柱状图使用同一组可信数据。
- 标明学生自述的历史考试成绩及其满分，不能把不同考试直接拼成能力进步曲线。
- 展示题号与知识点证据，区分“未测”“未答”“答错”，不凭空生成班级排名、百分位或不存在的历史趋势。
- AI 负责把统计结果转化为学生看得懂的诊断和建议，服务失败仍能生成明确标识的规则版报告。
- 用适合学生、家长和教师阅读的语言描述当前表现，图表只代表本次有限题量的测评，不包装成权威能力鉴定。
- PDF 使用可嵌入的中文字体、矢量图表、统一标题和页码；长姓名、长题干、零分、全对和缺失自述成绩均需检查。
- PDF 由服务端根据已保存且属于当前学生的报告生成；下载接口校验身份，不提供可猜测的公开文件地址。

## 四、界面精简

- 一级导航建议保留：学习首页、数学学习、错题本、诊断报告、AI 教练。
- 互动教学、教材资料放在数学学习页内；学习档案、个人设置放在用户菜单中。
- 新首页聚焦“继续测评 / 查看诊断 / 下一项数学学习”，减少重复卡片和统计面板。
- 语文、英语从导航、首页卡片、今日推荐和资料筛选入口同时隐藏，避免只隐藏菜单却仍要求完成三科任务。
- 通过集中功能开关控制学科可见性；旧链接给予清晰的暂未开放说明，历史数据仍保留。
- 第一版不删除原有其他年级互动课件；它们作为数学学习中的扩展资源，不参与六升七初测评分。

## 五、实现边界和依赖选择（待确认）

- 新增独立的入学档案、诊断试卷/作答、报告存储，使用增量 SQLite 建表；不把可信评分写进可由客户端自由修改的通用草稿。
- 新增后端访谈、组卷、保存作答、提交判分、报告读取和 PDF 下载接口，经现有同源前端接口转发。
- 复用现有 AI 服务选择、密钥保护、超时与限流机制；初次 AI 访谈和报告解读会消耗配置服务的调用额度。
- 推荐新增 ReportLab 作为后端 PDF 依赖，用于中文分页排版和矢量图表。当前后端 Python 环境尚未安装该库。
- 替代方案一：浏览器打印另存为 PDF，无新增 PDF 库，但操作多一步且分页依赖浏览器。
- 替代方案二：复用本机已安装的 Playwright 渲染 HTML 成 PDF；实际部署还需浏览器运行环境，部署体积和维护成本更高。
- ReportLab 的影响：需要安装并登记依赖、提供可用中文字体及部署说明；不需要外部 PDF 服务。用户确认前不安装。

## 六、模块位置与代码风格

- 前端页面/组件：`frontend/app`，新增独立访谈、测评、报告组件，与现有会话层集成。
- 可信题库：`shared/curriculum` 下新增数学衔接题库目录。
- 后端：沿用 `backend/app/api`、`schemas`、`services`、`repositories` 分层，报告与测评各自独立模块。
- 测试：`frontend/tests`、`backend/tests`；验收说明保存在 `docs`。
- 关键业务逻辑使用中文注释，命名说明实际含义；计分函数保持纯函数，AI 文本生成与数值计算分开。

例如：

```python
def calculate_dimension_accuracy(correct_count: int, question_count: int) -> float | None:
    # 未测维度不以零分替代，避免报告把缺少数据误判为能力薄弱。
    if question_count == 0:
        return None
    return round(correct_count * 100 / question_count, 1)
```
